Tier 1

Fix Today — Four Findings on Your Live Site

These came from a review of your live homepage. Each is specific, verifiable, and fixable in under an hour — clearing real obstacles for phone users and search engines before you touch a single layout.

Fix Now

1. Your site tells phones "don't let people zoom"

The short version: Divi ships with a setting baked into its code that blocks pinch-to-zoom on phones. There's no switch for it in Theme Options — but a free plugin fixes it in two minutes, no code needed.

Why this matters

Zooming is how people with less-than-perfect vision read small text and inspect detail — and your audience of hobbyist woodworkers studying CNC technique leans on it more than most. Blocking it is a recognized accessibility failure (WCAG guideline 1.4.4, "Resize Text").

It also shows up as a flagged error in Google's PageSpeed accessibility audit, dragging down a score you'll want green when you start working on SEO. Some modern phone browsers quietly ignore the block and allow zoom anyway — but not all do, and the audit penalty applies either way. Sites have jumped 15–20 accessibility points from this one fix.

Step-by-step fix (two options)

Option A — Code Snippets plugin, no child theme needed (recommended)

The free Code Snippets plugin (search it in Plugins → Add New; over 900,000 active installs) lets you paste PHP code into WordPress safely — no theme editing, no files. It's the most widely recommended method across the Divi community in 2025–2026.

  1. Install and activate Code Snippets from the Plugin Directory.
  2. Go to Snippets → Add New. Give it a name like "Fix Divi zoom."
  3. Paste this code exactly:
// Remove Divi's zoom-blocking viewport tag
function tf_remove_divi_viewport() {
  remove_action( 'wp_head', 'et_add_viewport_meta' );
}
add_action( 'wp_loaded', 'tf_remove_divi_viewport' );

// Replace it with an accessible, zoom-friendly version
function tf_zoom_friendly_viewport() {
  echo '<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=5.0, user-scalable=1, viewport-fit=cover" />';
}
add_action( 'wp_head', 'tf_zoom_friendly_viewport' );
  1. Set the snippet to run everywhere, then click Save Changes and Activate.
  2. Clear your site cache (if you use a caching plugin or Cloudflare), then test on your phone — pinch-zoom should now work.
  3. Re-run PageSpeed Insights. This single fix routinely moves accessibility scores up 15–20 points.

Why these values: maximum-scale=5.0 is the minimum Google's audit requires (not 2.0 — 5× zoom). user-scalable=1 explicitly enables scaling. viewport-fit=cover prevents content from being hidden behind iPhone notches and rounded corners as a bonus.

Option B — Divi child theme's functions.php (cleanest, if you already have one)

Paste the same code block above into your child theme's functions.php. Never edit Divi's parent theme files directly — theme updates will erase your changes. If you don't have a child theme set up yet, Option A is faster and equally effective.

Not sure which to choose or want a guided walkthrough? Use Prompt 1 in Section 2.

Fix Now

2. Your images are invisible to Google — and to screen readers

The short version: Your hero and menu-card images have names like ChatGPT-Image-May-19-2026-06_03_17-PM.png and no real descriptions. Rename future uploads, and add a one-line description ("alt text") to every existing image in the Media Library.

Why this matters

Google can't "see" pictures — it reads their filenames and alt text. Right now those say nothing about CNC, Carveco, or woodworking, so your images earn you zero search visibility, including in Google Images where woodworkers genuinely browse for project ideas.

Alt text is also what a screen reader speaks aloud. Your image cards are your main navigation — Academy, Shop, Discord, Sell. A visitor using a screen reader currently hears a ChatGPT timestamp where your most important buttons should be.

Step-by-step fix
  1. Future uploads: rename files before uploading — timberfalls-academy-carveco-courses.png, not a timestamp. WordPress locks the filename at upload, so this is a habit, not a retrofit.
  2. Existing images: in Media Library, click each image and fill the Alt Text field. Describe what it shows and where it leads: "Timberfalls Academy — Carveco Maker video courses."
  3. One Divi quirk: an Image module copies the alt text at the moment you insert the image. If you edit alt text in the Media Library later, modules already on the page keep the old version — so also check each image module (settings → Advanced → Attributes) and update its alt there.
High

3. Three footer links go nowhere, and one social icon is mislabeled

The short version: In your footer, Facebook, Instagram, and Contact are placeholder links (they point to "#" — literally nothing). And the X (Twitter) icon in your header is labeled "Follow on Facebook" — a copy-paste leftover. Five minutes in the Theme Builder fixes all four.

Why this matters

Dead links read as "unfinished" to visitors weighing whether to buy a course, and they waste the limited attention search engines give your site on each visit. The mislabeled icon is an accessibility defect too: a screen-reader user is told they're headed to Facebook and lands on X.

These are the cheapest trust wins on the whole list.

Step-by-step fix
  1. Open Divi → Theme Builder and edit your global footer template.
  2. Replace each # link with the real URL — or remove the link entirely until the destination exists. (An honest absence beats a dead link.)
  3. In the header's social-follow module, open the X icon's settings and correct its title/label to "Follow on X."
  4. While you're there: your footer's Coaching, Sell, and Dashboard links use different web addresses than the same links in your main menu. Click every footer link once and confirm each lands where you expect.
Quick Win

4. Your homepage introduces itself to Google as "Home"

The short version: When someone shares timberfalls.us in a Facebook woodworking group — your exact audience — the preview card is titled "Home." The homepage title is your single strongest search lever, and right now it's spent on nothing. Fix it in Rank Math (Section 3) in two minutes.

Why this matters

The page title is what shows as the blue headline in Google results and as the bold text on shared-link preview cards. It's weighed heavily for ranking and it's what convinces a human to click. You want it carrying the words your customers actually type: CNC files, Carveco training, CNC designs — not "Home."

Step-by-step fix
  1. Install Rank Math first (Section 3, item 2).
  2. Edit the homepage, and in the Rank Math panel set the title to something like: "CNC Files, Designs & Carveco Maker Training | Timberfalls."
  3. Write a one-to-two sentence description mentioning the Academy, the design shop, and 1-on-1 coaching — that's the gray text under the blue headline in Google.
  4. Rank Math automatically makes the shared-link preview title match. Test it by pasting your URL into a Facebook post draft (you don't have to publish).

Tier 2

The Divi 5 Mobile Method

Divi 5's mobile tools are genuinely different from Divi 4 — better, but different enough that most tutorials (and most AI answers, unless you tell them otherwise) describe the old version. Learn five concepts and one workflow, and every mobile fix becomes the same repeatable move.

Five concepts that do all the work

  • Seven breakpoints, three on by defaultA "breakpoint" is a screen width where your layout is allowed to change. Divi 5 offers seven — Phone through Ultra Wide — with Phone, Tablet, and Desktop active out of the box. Manage them via the three-dot menu next to the device icons in the builder's top bar (Sitewide Responsive Breakpoints). The default three are enough until a layout genuinely breaks between them.
  • The Responsive Editor panelNext to nearly every setting sits a small responsive icon. Click it to see and edit that setting for every screen size side-by-side — no bouncing between preview modes. It turns blue wherever a per-device override exists, so you can spot every mobile customization at a glance.
  • Inheritance flows downwardAny screen size you leave blank simply copies the next larger one. Desktop is the master value; a Phone override changes Phone only. This is your safety net — you can fix mobile aggressively without ever touching the desktop design.
  • Fluid sizing with clamp()Divi 5's input fields accept modern CSS math. clamp(1.5rem, 4vw, 3rem) for a heading means: never smaller than the first number, never bigger than the last, scale smoothly in between. One fluid value often replaces three separate per-device overrides.
  • One gotcha: visibility togglesThe show/hide-this-element-per-device switches currently work only for the original three sizes (Phone, Tablet, Desktop) — not the extra custom breakpoints. Plan any "hide this on mobile" moves around those three.
  • Structure Templates for quick column changesNeed a three-column desktop row to become a single column on phones? Use Structure Templates at the row level — it swaps column layouts per breakpoint without rebuilding the section. Much faster than recreating a layout from scratch for mobile.

The repeatable workflow

  1. Lock desktop first. Your desktop layout is where you want it — treat it as read-only from here on.
  2. Switch the canvas to Phone using the device icons in the top bar, and scroll the entire page top to bottom. Note every break: overflowing text, oversized images, cramped buttons, sections in the wrong order.
  3. Fix each break at the Phone breakpoint only. Click the element to open its settings. Use the state picker inside the settings panel to select the Phone breakpoint — this keeps responsive and interaction-state editing (Hover, Focus, Sticky) in one workflow. Set a Phone-specific value via the Responsive Editor for the offending property. Inheritance guarantees desktop is untouched.
  4. Prefer fluid values over stacked overrides. Overriding a font size at three screen sizes? Replace all three with one clamp() value at the desktop level instead.
  5. Fix type once with presets. Edit the H1/H2/body presets (not individual modules) with per-breakpoint sizes, and every heading site-wide inherits the fix.
  6. Audit with the blue icons. Turn on the Modified Settings filter in an element's options to list only changed settings — your map of every responsive override, and the first place to look when something misbehaves later.
  7. Verify on a real phone. The builder preview is good; your actual thumb on your actual phone is the truth. Check tap targets especially — buttons and links should be comfortably tappable (roughly 44px or larger).

Tier 3

SEO Starter — Structure First, Then Measure

You don't need an agency to get the fundamentals right. Timberfalls has something most sites would kill for: a genuinely specific niche — Carveco training plus CNC design files — with clear buyer language. The job is making sure Google can see that.

1. Give every page one clear job

Search engines reward sites where each page targets one clear intent — one kind of visitor, one goal.

What that means for each of your pages
  • Homepage → broad brand terms: CNC files, CNC designs, Carveco training (see Finding 4 — this is the title fix).
  • Academy page → learning intent: Carveco Maker course, learn CNC carving, CNC training for beginners.
  • Shop & individual designs → buying intent: CNC-ready files, STL/SVG designs for [project type]. Every product page needs its own descriptive title, not a filename.
  • Coaching page → service intent: 1-on-1 Carveco coaching — and those glowing testimonials you already have are exactly what should live here, near the booking button.

Within each page: one H1 that states the topic, then H2s for sections. Divi makes it tempting to pick heading levels for their looks — pick them for structure and control the looks with presets instead.

2. Install an SEO plugin and run its setup wizard

Start with Yoast SEO (free). It's the most beginner-friendly option — every suggestion comes with a plain-English explanation of what to fix and why, using a simple red/yellow/green system. For a first SEO setup, that guided approach is more valuable than a longer feature list.

Why Yoast first — and when to consider Rank Math instead

In 2026, the two dominant WordPress SEO plugins are Yoast SEO and Rank Math, and both handle the fundamentals (titles, descriptions, sitemaps, schema, Open Graph) competently. The difference is who they're built for:

Yoast is the better starting point if you're new to SEO. Its traffic-light scoring system, readability analysis, and per-suggestion explanations teach you SEO while you use it — you'll understand why a fix matters, not just that it needs doing. 10+ million active installs, excellent Divi compatibility, and 15 years of WordPress support track record.

Rank Math is the better choice once you're comfortable with the basics, or if you want maximum features for free: its free tier includes a redirect manager, 404 monitoring, Google Search Console integration inside WordPress, and 18 schema types — features Yoast gates behind a paid Premium plan. The trade-off is a steeper learning curve; the settings panel is dense, and it can feel overwhelming for a first setup.

The one firm rule: never run both at the same time. Duplicate meta tags, competing sitemaps, and conflicting schema markup will actively hurt your SEO. Pick one, install it, and if you later want to switch, Rank Math's setup wizard imports all your Yoast data automatically.

During either plugin's setup wizard, connect your Google account when prompted — it links Google Search Console automatically and starts collecting the real-world search data you'll need for the next step.

3. Measure with free tools, then let AI read the report

Two free Google tools tell you everything: PageSpeed Insights (pagespeed.web.dev) scores your mobile experience and lists exact problems, and Google Search Console shows the real search terms people use to find you — which beats guessing keywords. Run PageSpeed, then paste the results into Prompt 4 and let AI turn the report into a ranked to-do list.

How to run PageSpeed Insights (2 minutes)
  1. Go to pagespeed.web.dev, enter timberfalls.us, and run the test.
  2. Make sure the Mobile tab is selected — that's the score Google cares about most, and the one your visitors live in.
  3. Scroll past the scores to the diagnostics list. Select and copy that text.
  4. Paste it into Prompt 4 below. Re-run the test after each round of fixes to watch the scores climb — the zoom fix from Finding 1 alone should move your accessibility number.
